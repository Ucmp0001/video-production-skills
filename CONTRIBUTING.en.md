# Contributing

[简体中文](CONTRIBUTING.md) · [English home](README.en.md)

Prefer experience that changes production decisions: concrete inputs, an observed problem, the smallest useful fix, recheck results and conditions where the lesson applies. Scope one-off failures and personal aesthetic preferences instead of turning them into universal bans.

Keep each skill focused on one task. `SKILL.md` contains triggers, necessary inputs, decision rules and deliverables. Put longer templates in `references`; script only repeatable, deterministic checks. New scripts should use the standard library or document necessary dependencies, without introducing private service wrappers.

## Keep both languages useful
Update matching Chinese and English instructions when behavior changes. Keep a single canonical discovery file, `SKILL.md`, routing English tasks to `SKILL.en.md`. Match reference templates and beginner examples too. Translate the meaning and constraints, not just headings. Commands, skill names and executable code remain shared.

Before submitting, run the structure/link validator, privacy scan and tests listed in the README. Use minimal fictional or authorized examples. Never commit raw logs, authentication files, private voice IDs, private paths, client material, paid receipts, real footage or old private Git history. Report sanitized symptoms and locations only; never paste secrets into public issues.

Judge skill quality through actual tasks. Adding a heading, passing structural validation or a model approving its own output does not establish finished-video quality.
