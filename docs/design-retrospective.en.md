# Why these 11 skills?

[简体中文](design-retrospective.md) · [English home](../README.en.md)

## From one project to independent use
The original workflow combined useful production experience with a particular computer, folder layout, brand, voice, models and historical task conventions. The public version retains quality decisions while leaving environment and creative preferences to the user. It includes no private service entrypoints and does not claim automatic external-tool execution.

## How the boundaries were chosen
Three questions: can the task be triggered independently, are its inputs/outputs clear, and can it still produce useful work outside the original project?

| Original responsibilities | Public skill | Reason |
|---|---|---|
| Coordination and shared constraints | video-workflow | Owns starting point, dependencies, status and revision impact without repeating every stage |
| Import and video understanding | video-source-index | One source and timeline connect acquisition to usable intervals |
| Voiceover and factual boundaries | evidence-story-script | Story promises must remain connected to evidence |
| Shots, gaps and visual preflight | video-shot-planner | One shot plan connects selection to implementation |
| Motion methods and creative prompts | explainer-motion | Prompts support observable state changes, not slogans |
| Generated video and paid-task recovery | generated-broll | Budget, task state, original output and conceptual nature belong together |
| Voice, measured timing and captions | voice-subtitle-sync | Audio changes affect the whole timeline; prevent stale handoffs |
| Cover creation | cover-art-direction | Copy, visual relationships and ratio adaptation need dedicated design |
| Cover acceptance | cover-independent-review | The creator cannot independently approve their own work; inspect actual exports |
| Final review and platform packaging | video-release-qa | Shares the final version while distinguishing export review from platform copy |
| Reference learning and reusable lessons | video-reference-study | A learning request should not automatically trigger production |

Eleven is this version's interface choice, not a universal optimum. Whiteboard videos, investigations, editing applications, Remotion, individual TTS providers and H3 are optional implementation routes rather than separate tool adapters here: their complete installers, renderers and service clients are not included. Check official documentation for the user's installed versions.

## Lessons retained
- The opening image and first sentence ask the same question; the body answers it.
- Check key asset availability during research. Track factual sources separately from media rights.
- Visuals supply evidence, action, scale or mechanisms instead of filling the video with static noun cards.
- Preview a complete event likely to expose problems before scaling up the approach.
- Separate global, shot and source clocks; use real audio for final timing.
- Track technical checks, stills, motion, sound, sources, covers and publication conditions separately.
- Recover unclear generation tasks first; changed paid plans do not inherit old authorization.
- Recompose ratios; phone readability matters more than arbitrary headline character limits.

## Removed details and capability limits
Names, private account branding, personal theories, fixed sign-offs, private media, screenshots, voice references, music files, accounts, paid receipts, absolute paths and internal logs are excluded. Creator/reviewer models are configurable, while actual receipts and explicit context delivery remain required.

This package provides instructions and small checks, not a complete automatic video factory, software installation service, authentication, legal guarantee, full audiovisual capability or audience guarantee. See [validation scope](validation.en.md). Use anonymized minimal cases to learn from new production problems.
