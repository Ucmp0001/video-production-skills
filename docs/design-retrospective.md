# 为什么拆成这 11 个技能
## 从单个项目走向独立使用
原来的工作流积累了有效的制作经验，也混合了特定电脑、目录、品牌、声音、模型和历史任务约定。开源版保留影响质量的判断，将环境与作者偏好移交给使用者配置；不沿用私有服务入口或声称自动完成外部工具调用。

## 拆分依据
三个判断：任务能否独立触发，输入输出是否清楚，离开原项目是否仍能完成有意义的工作。

| 原有职责组合 | 本版选择 | 原因 |
|---|---|---|
| 视频总控与共享约束 | video-workflow | 只负责起点、依赖、状态与修改影响，不重复各工序 |
| 素材导入与视频理解 | video-source-index | 同一原片与时间码，导入到可复用区间是完整任务 |
| 短视频口播与事实边界 | evidence-story-script | 故事承诺与证据不能分开后相互失配 |
| 分镜、素材缺口、镜头预检 | video-shot-planner | 一张镜头表贯通选材与实现 |
| 动效方法与创作提示词 | explainer-motion | 提示词服务可见状态变化，避免只交口号 |
| AI 视频与付费任务恢复 | generated-broll | 预算、服务任务状态、原始输出与事实性质边界明确 |
| 配音、实测时间与字幕 | voice-subtitle-sync | 音频变化影响全片时序，避免互相沿用过期文件 |
| 封面主创 | cover-art-direction | 稳定文案、视觉关系、比例重排需要专门设计 |
| 封面验收 | cover-independent-review | 创作者不能自签独立通过，必须观察真实导出图 |
| 内容复核与平台包装 | video-release-qa | 共享最终版本，区分成片审阅和逐平台文案两种模式 |
| 参考片学习与经验提炼 | video-reference-study | 用户可能只想学习，不应自动进入整片生产 |

11 个是本次接口选择，不是固定最佳数量。没有把白板、调查片、剪映、Remotion、某家 TTS 或 H3 单独包装成工具适配 skill：完整安装器、渲染器或服务客户端未随本仓库提供，这些先是可选实现路线。工具调用细节继续查使用者安装版本的官方文档。

## 保留下来的关键经验
- 开头的画面和第一句话提出同一问题，正文能兑现。
- 研究时就验证关键素材可得性，事实来源与媒体使用权分别登记。
- 画面提供证据、动作、尺度或机制变化；不靠静态名词卡填满全片。
- 用最容易暴露问题的完整事件做短预览，然后扩展已验证做法。
- 明确全片、镜头与素材三种时钟，使用真实音频建立最终时间线。
- 技术、画面、连续运动、声音、来源、封面和发布条件分项记录。
- 生成结果不明先恢复原任务，重试不继承已改变计划的授权。
- 比例适配重新构图，手机可读优先于机械的标题字数上限。

## 抽离与未声称的能力
移除姓名、账号品牌、个人理论、固定结束语、私人素材、参考截图、音色引用、音乐文件、账户、付费记录、绝对路径和内部日志。模型主创与复核可配置，保留真实回执与输入送达要求。

本版提供指导与小型校验工具，不提供全自动视频生产、工具安装、服务认证、法务保证、全片视听能力或流量保证。初版的验证范围详见 validation.md；真实制作中的新问题应通过匿名最小案例复盘。
