# Explanatory motion

[中文 / canonical entry](SKILL.md)

Help viewers see how relationships change. Use for mechanisms, causality, processes, scale, comparisons and data, while retaining valuable real footage.

## Direction inputs
Use the [motion brief](references/motion-brief.en.md) to establish the audience question, verified content and assumptions, initial/result states, trigger, attention order, actual audio anchors, current project and safe areas.

Use 2D for relationships, processes and data; 3D for objects, depth, scale and spatial movement. Combine them around the same explanation. Keep simple relationships simple; not every shot needs 3D. Hold the content constant while comparing material, space, movement and readability. Recoloring alone does not demonstrate a mechanism.

## Implementation
Use the user's existing Remotion, SVG/HTML, Canvas, Three.js or editing tools after checking versions and capabilities. A tutorial does not authorize installing tools, replacing the stack or switching models. If a creator/model is specified, supply the necessary script, source, readable attachments and actual interfaces; a link or local path does not prove receipt.

Separate state, layout and rendering enough to maintain the work. Seekable rendering must be determined by frame/time and inputs: seed randomness, avoid cumulative drift and reproduce the same state with repeated or out-of-order seeks. Replay physics with fixed steps or verified checkpoints.

When count, area or length represents data, calculate from real values or explicit assumptions. Avoid precise labels on transitions that do not carry precise measurements. Reveal conclusions after the change is readable. Preserve object identity and continuity. Lighting, response layers, sound and camera movement serve the main event; avoid constant bouncing, decorative arrows and text slideshows.

## Preview and revise
Preview a complete representative event and its joins with the actual audio. Watch normal-speed motion and inspect before/after frames as needed; listen to narration and sound events. Record still checks, decoding, waveforms and code review separately; none establishes audiovisual acceptance.

Check values, assumptions, reading time, triggers, global/local clocks, occlusion and phone-size readability. If observation is unavailable, deliver “implemented; audiovisual acceptance pending” with specific intervals. Fix explanation and sync errors before surface polish. Subtitle/Logo-only edits do not require remaking the entire mechanism.

Deliver the brief, event table, maintainable source, dependencies/run instructions, preview, actual observation scope, revision decisions and current export. State unavailable tools/models and pending work without claiming a finished video.
