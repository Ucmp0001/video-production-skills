# Motion brief and implementation handoff

[中文](motion-brief.md)

## Inputs
1. Audience and explanation goal.
2. Verified claims, values, definitions and assumptions.
3. Object identities, initial state and result.
4. Trigger, main event and response layers.
5. Attention order, result reveal and reading hold.
6. Reasons for 2D/3D, materials, space, camera and style.
7. Measured voice/beat anchors, safe areas, captions and Logo.
8. Current project, versions, dependencies, interfaces, assets and permissions.

## Creator request
“Explain the target mechanism using the supplied content. First provide object states, event order, time/frame coordinates and a representative preview plan. Implement within the current project interface. Preserve qualifiers and data relationships. State missing assets or timing rather than inventing paths or anchors.”

## Implementation checks
Actual fps/Composition, complete relevant components and props, fonts/images, path conventions, run entrypoint, frame range and dimensions. Repeated/random seeks must reproduce frames. Check clocks for speed changes, crops, loops and nesting.

Start with composition, then preview a complete event. Record actual viewed/heard intervals and minimal fixes. If a read-only model returns code, the executing assistant reviews, saves and renders it; a design report is not a video.
